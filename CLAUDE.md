# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CFOP (Rubik's cube speedsolving method) tutorial app for Windows and Android. Tauri v2 shell, React 19 + TypeScript + Vite frontend, shadcn/ui (Base UI flavor) + Tailwind v4. Content: notation, beginner's (layer-by-layer) method, beginner CFOP (intuitive F2L, 2-look OLL = OLL 2, 44, 45, 21–27; 2-look PLL = T, Y, Ua, Ub, H, Z), full OLL/PLL. Algorithms follow speedcubedb.com; videos come from the SpeedCubeDB YouTube channel.

## Commands

```
npm run tauri dev            # run desktop app (starts Vite on :1420 automatically)
npm run dev                  # frontend only in a browser (Tauri plugins won't work)
npm run build                # type-check (tsc) + Vite build into dist/ — the only frontend check
npm run tauri android build -- --apk --target aarch64   # signed release APK (needs keystore.properties)
npx shadcn@latest add <component>                       # add a shadcn component to src/components/ui
```

Android builds locally need `JAVA_HOME` = Android Studio's `jbr` (JDK 21; the system JDK 26 is too new for Gradle), `ANDROID_HOME`, and `NDK_HOME` = `$ANDROID_HOME/ndk/28.2.13676358`.

Rust checks, from `src-tauri/`: `cargo check`, `cargo clippy`.

## Releasing

Bump the version in `package.json`, `src-tauri/tauri.conf.json` and `src-tauri/Cargo.toml`, push, then push a `vX.Y.Z` tag. `.github/workflows/release.yml` builds the Windows installer (+ `latest.json` for the updater) and a signed APK into a GitHub Release. Signing keys come from repo secrets; never regenerate them — installed apps can only update if the keys stay the same.

## Architecture

- **Routing** (`src/router.tsx`): `createHashRouter` (Tauri's custom protocol has no server fallback for deep paths). Every route renders inside `AppLayout`; a route's `handle.title` (string or `(params) => string`) becomes the header title.
- **Navigation** (`src/lib/nav.ts`): single source for the sidebar and home page cards. Adding a page = add a route + a `NAV` entry.
- **Alg data** (`src/data/`): `oll.ts` / `pll.ts` / `f2l.ts` (F2L 1–24, both pieces in the top layer) are generated by `npm run import-algs` (scrapes speedcubedb.com; re-running overwrites them, so review the diff). Only algs with a SpeedCubeDB video are kept (each alg has its own `videoId`); `algs[0]` is speedcubedb's standard alg when it has a video. Case pages show the video plus its alg — no 3D cube, by the user's choice. For F2L the importer simulates each case with cubing.js (dev dependency) to draw its top-down stickers, sort it into the Intuitive F2L categories (white on top / same / different top colors), and assert every alg solves the pair. `two-look.ts` doesn't copy algs — it lists case ids into the full sets, with an optional `algIndex` for a beginner-friendlier alg.
- **Lesson content**: beginner steps in `src/data/beginner.ts`; Intuitive F2L, Notation and Finger tricks keep their content inline in `src/pages/`. Every alg and piece-position description was checked on a simulated cube (cubing.js `kpuzzle`, a dev dependency — never import it from `src/`) — re-check any alg or "white facing right"-style description you change the same way.
- **Diagrams**: `CaseDiagram` draws a top-down last layer from the speedcubedb sticker strings; with `arrows` (PLL) it derives piece-movement arrows from the colors, choosing the U turn that leaves the fewest pieces moving. `MoveDiagram` is a front view for single moves.
- **Trigger names**: `src/data/triggers.ts` is the one trigger list (Triggers page + `splitTriggers` in `src/lib/triggers.ts`). Render algs through `AlgText`, which swaps in trigger names when the persisted `useSettings().triggerNames` is on; matches never cut one of the alg's parenthesized groups in half.
- **Leading y rotations** (`src/lib/alg-view.ts`): an alg starting with `y`/`y'`/`y2` is displayed without it, its `CaseDiagram` gets `rotate` (y = 90° clockwise), and the practice setup goes through `setupForView`. Data files keep the raw speedcubedb alg; apply `algView` wherever an alg and its diagram are shown together.
- **Cube model** (`src/lib/cube.ts`): tiny sticker model (yellow top, green front) supporting face, wide, slice and rotation moves; `cubeFaces` returns faces in the same layout as `IsoCube`/`CaseDiagram`/`CubeNet`. It reproduces speedcubedb's picture for all 78 OLL/PLL setups — re-run that check after changing it. Powers the Notation scramble drill. Quizzes use the shared `Quiz` component (`src/components/quiz.tsx`).
- **Progress** (`src/stores/progress.ts`): zustand store persisted to localStorage, keyed `"<set>:<caseId>"` (e.g. `oll:27`, `pll:T`) with status `learning | learned`.
- **shadcn components use Base UI**, not Radix: compose with the `render` prop (`<SidebarMenuButton render={<NavLink to="/x" />} />`), not `asChild`. `cn` comes from the `cn` package (shadcn's clsx + tailwind-merge replacement).
- **Updates** (`src/updater.ts`): desktop uses the Tauri updater plugin; Android has none, so it compares against the GitHub releases API and opens the APK download.
- **Platform split**: the updater plugin is desktop-only — its Cargo dependency is under a non-mobile target, it's registered under `#[cfg(desktop)]` in `lib.rs`, and its permissions live in `capabilities/desktop.json`. Keep anything desktop-only behind all three.
- **Rust**: all setup lives in `src-tauri/src/lib.rs`; `main.rs` only calls `run()`, which carries the mobile entry point. There are no custom commands.
- **Plugins** need the Cargo dependency, `.plugin(...)` in `lib.rs`, the npm package, and a permission in `src-tauri/capabilities/`. A missing permission fails at runtime, not compile time.
- Port 1420 is set in both `vite.config.ts` (`strictPort`) and `tauri.conf.json` (`devUrl`); change both together.
- `src-tauri/gen/schemas` is generated. `src-tauri/gen/android` is committed and hand-edited only for release signing in `app/build.gradle.kts`.
